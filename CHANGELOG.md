# 0.2.0 Beta

- Export Singulo 0.21 liquid-input variants for supported Android workbench recipes, alongside ordinary bucket patterns.
- Keep materials and refunds in per-request escrow. No machine processing or liquid main products.

# Changelog

## 0.1.0 (Beta, unreleased)

- Initialize the NeoForge 1.21.1 addon skeleton, metadata, naming and CI.
- Add AE2 encoded-pattern output decoding and player-authorized Android order commands using the unreleased Singulo 0.18.0 API.
- Add real-AE2 pattern GameTests.
- Require the published Singulo 0.18.0+ (0.18.x). Gradle downloads and SHA-256-verifies Singulo, AE2 and GuideME, so `./gradlew runClient` works without arguments.
- Add the Android Crafting Bridge: an AE2 crafting machine that escrows pattern materials, submits a Singulo Android order per push (all-or-nothing), receives the outputs from a linked Delivery Port and returns them to ME through the Pattern Provider.
- Add `/appliedsingulo snapshot` and `/appliedsingulo bridge <pos> status|cancel`.
- Add the Android ME Interface: an ME cable node placed against a Work Console. Recipe Rack recipes are shared to AE2 as patterns automatically; materials go straight to the androids and outputs are pulled from the console outbox into ME. No Pattern Provider, Supply Port or Delivery Port needed.
- Batch AE2 pushes of the same output into one Android order (up to 4096) for both the bridge and the ME interface. Escrow grows to 108 stacks.
- Require Singulo 0.19.0 (unreleased; built from a pinned `feature/0.19.0` commit) and move both devices to its private crafting escrow (`AndroidEscrows`): batched AE2 materials belong to one request only, products and leftovers are claimed back by request id and returned to ME, and requests are acknowledged only once empty. Supply/Delivery Ports and adjacency are no longer needed; the console is chosen with a Work Location Card or by placing the device against it.
- Share only escrow-eligible crafting recipes (no processing, procedures, fuel, catalysts or liquids); the bridge refuses pushes without such a recipe.
- Recover requests of broken devices and drop their products and materials where the device stood.
- Pin Singulo `bed2d08b` (escrow trip-size fix): large AE2 orders at Android Workbenches no longer make the android fetch and return materials forever.
- The ME interface placed against a Supply Port (or the Work Console) shows its ME network's stored items to Singulo as storage, like QIO. One network is counted once however many interfaces touch the console's ports (Singulo `AndroidSharedStorage`, pinned `9dd8251d`), and only the owner's own Supply Ports/console can see or insert.
- Chained patterns: when Recipe Racks also hold the recipes of intermediates, the ME interface offers AE2 a raw-materials-to-product pattern (e.g. 5 logs -> 12 fences) listed before the single steps, so AE2 pushes once and Singulo crafts the whole chain in one escrow order (needs Singulo multi-step escrow). Without the raw materials AE2 falls back to the single-step patterns.
- Chained patterns are offered by a second internal grid node at a higher pattern priority. AE2 orders the patterns of one item only by provider priority (equal priorities come out in hash order), so the chain was sometimes skipped and AE2 ordered planks, sticks and fences separately.
- Pin Singulo `d09ff94f`: androids keep taking from a storage slot that holds more than one stack (ME view, QIO), so Singulo orders served from ME no longer stop at "waiting for space" after one stack.
- Diagnostics: the ME interface status lists recent AE2 pushes as [chain] or [step], and every escrow request is logged.
- Remove the Android Crafting Bridge; the Android ME Interface is the only device. `/appliedsingulo bridge` becomes `/appliedsingulo interface <pos> status|cancel` (blocks and panels).
- Add the Android ME Interface Panel (AE2 cable part, 1:1 craftable with the block); it shows ME storage only to the block it faces.
- AE2-style status screen (AE2 menu/screen framework) replaces the chat output: connection, console, recipes, orders with icons and progress, buffers, last refusal, recent pushes, Shift-click "cancel all", and AE2's standard priority screen (pattern priority; chains use priority + 1).
- New block/panel textures (AE2-like interface frame with Singulo accents), generated by `tools/gen_textures.py`.
- The status screen now follows AE2's ME Interface layout: AE2 palette and slot frames, an orders slot row with state bars and tooltips, a waiting-for-ME slot row, and the player inventory.
- The waiting-for-ME row is made of real insert-only slots: players can deposit items (also by shift-click) and they are sent into ME.
- Android Status Emitter (cable part): redstone from the order state of all Android ME Interfaces on the network (stuck / busy / idle, right-click to cycle).
- Android Order Monitor (cable panel): shows the current order's product, progress and order counts, like AE2's storage monitor.
- Keep in stock: 9 slots per interface; when ME holds less than the target, an AE2 crafting job is started (made by the androids). Needs a crafting CPU.
- Machine (processing) recipes and fluid materials: shared as AE2 patterns (fluids as AE2 fluid inputs) and run in private escrow (Singulo multi-step escrow with machines and fluids). Fuel, catalysts, chemicals and liquid main products stay unsupported.
